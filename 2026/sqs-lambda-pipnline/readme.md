# AWS SQS + Lambda 기반 AI 영상 생성 파이프라인 구축

## 프로젝트 개요

최대 7,000명이 참여하는 오프라인 행사에서 참여자별 AI 캐릭터와 개인화 영상을 생성하는 시스템을 개발했다.

행사 시작 전과 종료 후 참여자 전원에게 리마인더 문자를 발송하는 구조였으며, 클라이언트 측 문자 발송에 따라 순간적으로 트래픽이 집중될 수 있었다. 이에 최대 2,000명 동시 접속을 고려하고, AI 이미지 및 영상 생성 작업이 집중되더라도 요청 처리 지연과 서버 부하를 최소화할 수 있도록 설계했다.

AI 생성 작업은 여러 단계로 구성되며 각 단계의 처리 시간이 일정하지 않았다. 따라서 API 요청 처리와 미디어 생성 작업을 분리하고, 작업 상태를 추적하면서 단계별로 안정적으로 처리할 수 있는 비동기 아키텍처를 구축했다.

## 1. AI 이미지 및 영상 생성 파이프라인

사용자가 이미지를 업로드하면 AI 캐릭터 이미지를 생성하고, 이를 기반으로 여러 영상 요소를 제작해 최종 결과물을 합성하도록 구성했다.

전체 파이프라인은 다음과 같다.

1. 사용자 이미지 업로드 및 AI 캐릭터 이미지 생성
2. 생성된 이미지를 4개 영역으로 분리
3. 분리된 이미지 중 2개는 로컬 모델을 이용해 배경을 제거한 뒤 저장
4. 외부 AI 모델을 통한 두 번째 영상 생성 및 저장
5. FFmpeg를 이용해 첫 번째 및 세 번째 영상 생성
6. 생성된 3개 영상을 합쳐 최종 영상 렌더링

외부 AI 모델을 통한 이미지·영상 생성과 FFmpeg 기반 영상 처리를 조합해 하나의 개인화 영상으로 완성하는 구조다. 특히 처리 단계별로 결과물을 분리해 저장하고, 각 작업의 완료 여부를 확인한 뒤 다음 단계로 진행하도록 구성했다.

## 2. SQS + Lambda 기반 비동기 처리 구조

AI 이미지 및 영상 생성 작업은 일반적인 API 요청보다 처리 시간이 길고, 여러 참여자의 요청이 동시에 유입될 수 있었다. 이를 메인 서버에서 직접 처리할 경우 요청량 증가에 따라 서버 리소스가 집중되고 응답 지연이 발생할 가능성이 있었다.  
특히 이전 프로젝트에서 영상 렌더링을 메인 서버에서 처리하다가 트래픽이 몰려 클러스터의 노드 전체가 OOM으로 다운된적이 있었기에 그때보다 더 많은 인원이 몰리는 상황이라 분리가 필요했다.  

이를 해결하기 위해 무거운 미디어 처리 작업을 AWS Lambda 기반 워커로 분리하고, SQS를 통해 작업을 전달하는 비동기 처리 구조를 구축했다.

- **작업 큐:** SQS에 처리할 작업을 적재해 요청 접수와 실제 작업 실행을 분리
- **비동기 워커:** Lambda가 큐에서 작업을 가져와 이미지 처리 및 영상 렌더링 수행
- **상태 동기화:** 작업 결과를 웹훅으로 메인 서버에 전달해 처리 상태 갱신
- **단계별 실행 제어:** 이전 단계가 정상적으로 완료된 경우에만 다음 단계 실행

이를 통해 메인 서버가 미디어 처리 작업을 직접 수행하지 않도록 하고, 작업량에 따라 비동기 워커가 처리하도록 구성했다.

## 3. 단계별 상태 관리 및 모니터링

전체 작업을 단순히 성공 또는 실패로 구분하는 대신, 각 처리 단계에 대해 대기, 실행 중, 성공, 실패, 재시도 상태를 관리하도록 설계했다.

각 단계의 처리 결과를 메인 서버에 전달함으로써 참여자별 진행 상황과 전체 작업 현황을 실시간으로 확인할 수 있도록 했다.

또한 단계별 완료 여부를 기준으로 후속 작업을 실행하도록 구성해, 앞선 단계가 완료되지 않은 상태에서 다음 단계가 진행되는 것을 방지했다.

이러한 구조를 통해 작업 진행 상황을 추적하고, 문제가 발생한 작업을 식별해 재처리할 수 있도록 했다.

## 4. 운영 결과

행사 당일 실제 서비스 운영 중 메인 서버와 Lambda의 리소스 사용률을 실시간으로 모니터링했다.

- 총 3,304건의 작업 완료
- 작업 처리 과정에서 시스템 차원의 실패 0건
- 메인 서버 및 Lambda 리소스 사용률 10% 미만 유지
- SQS 대기 메시지가 표시되는 상황에서도 워커가 작업을 지속적으로 가져가 처리해 실질적인 대기 지연을 최소화

AI 생성 결과물 자체의 품질 문제는 별도로 발생할 수 있었으나, 이는 작업 실행 실패와 구분해 관리했다. 품질 문제가 확인된 결과물은 이후 재처리했다.

## 정리

이번 프로젝트에서는 AI 이미지 및 영상 생성이라는 시간이 오래 걸리는 작업을 여러 단계로 분리하고, SQS와 Lambda를 이용해 비동기 처리 구조를 구축했다.

특히 단계별 상태 관리와 웹훅 기반 상태 동기화를 통해 다수의 작업 진행 상황을 추적할 수 있도록 했으며, 실제 행사 운영 중 리소스 사용률과 작업 처리 현황을 모니터링해 시스템이 정상적으로 동작하는지 확인했다.
